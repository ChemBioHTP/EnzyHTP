## Scope

This task focuses on full Amber bonded metal-center parameterization through `MCPB.py` inside the Amber `MolDynParameterizer` path.

Current status:

- `MetalUnit` / metal-like residues and `Structure` accessors already exist well enough for this milestone.

## Core Design Constraint

`MolDynParameterizer` is intentionally decoupled from any concrete `Structure` until `run(stru)` is called.

Therefore, MCPB configuration passed to `AmberInterface.build_md_parameterizer()` must not contain structure-bound objects or structure-specific atom/residue keys. Do not put any of the following in constructor-time config:

- `MetalUnit`, `Residue`, or `Atom` objects.
- `metal_key`, `additional_residue_keys`, `add_bonded_pairs`, or any other direct `(chain, residue, atom)` references.
- Precomputed `ion_ids` from a specific PDB atom numbering.

All structure-coupled facts must be derived inside `AmberParameterizer.run(stru)` from the `Structure` that is actually being parameterized:

- Which metal centers exist.
- The saved PDB atom IDs used by MCPB.py `ion_ids`.
- Donor atoms and metal-donor bonded pairs.
- Additional residues around the metal model.
- Peptide reconnection bonds around renamed MCPB residues.
- Any mapping between EnzyHTP residue/atom references and MCPB/tleap atom identifiers.

Constructor-time MCPB options should be workflow policy, not structure state. The completion test currently expresses the intended public surface as MCPB enablement plus MCPB.py process controls:

```python
param_method = interface.amber.build_md_parameterizer(
    force_fields=[
        "leaprc.protein.ff14SB",
        "leaprc.gaff",
        "leaprc.water.tip3p",
    ],
    charge_method="RESP",
    metal_center_method="mcpb",
    mcpb_add_redcrd=0,
    mcpb_anglefc_avg=0,
    mcpb_bondfc_avg=0,
    mcpb_cut_off=3.0,
    mcpb_ion_paraset="12_6",
    mcpb_large_opt=1,
    mcpb_scale_factor=1.0,
    mcpb_software_version="g16",
    mcpb_sqm_opt=0,
    mcpb_xstru=0,
    mcpb_step1_method="1a",
    mcpb_step2_method="2s",
    mcpb_step3_method="3b",
    mcpb_step4_method="4b",
)
params = param_method.run(stru)
```

The exact public names can change during implementation, but this separation cannot: the parameterizer may hold MCPB policy; only `run(stru)` may resolve metal-center topology. MCPB force-field choices should be derived from existing parameterizer attributes. For example, MCPB `force_field`, `water_model`, and `gaff` must be inferred from `force_fields` so they cannot drift from the final Amber parameterization settings. MCPB ion mol2 and QM-result lookup should use existing parameterizer/library/work-directory conventions rather than adding separate constructor paths unless a concrete missing use case appears.

Use MCPB.py input variable names for exposed MCPB controls where practical. In particular, the completion test uses `mcpb_cut_off`, not a second spelling such as `mcpb_cutoff`.

## MCPB.py Workflow To Support

Use the local environment:

```bash
source ~/bin/miniconda3/bin/activate new_enzy_htp
```

The available MCPB.py is AmberTools 23.6, `MCPB.py` version 7.0.

MCPB.py command shape:

```bash
MCPB.py -i input_file -s step_number [--logf gaussian_or_gamess_log] [--fchk gaussian_fchk]
```

Required MCPB input variables generated by EnzyHTP during `run(stru)`:

- `ion_ids`: atom IDs from the MCPB input PDB written for the current `Structure`.
- `ion_mol2files`: metal ion mol2 files resolved from existing parameter/NCAA-library conventions and the metal identity/charge.
- `original_pdb`: MCPB-compatible PDB written by the parameterizer for this `Structure`.

Important optional variables generated or configured during `run(stru)`:

Structure-derived variables:

- `add_bonded_pairs`: derived from the metal center donor atoms when needed.
- `additional_resids`: derived from the metal model selection policy when needed.
- `frcmod_files`: resolved from existing parameterization artifacts for involved ligands/modified residues.
- `group_name`: generated deterministically from structure-local metal identity, such as residue name/index plus a stable counter.
- `lgmodel_chg`, `lgmodel_spin`, `smmodel_chg`, `smmodel_spin`: derived from charge/spin data assigned on the current `Structure` where possible.
- `naa_mol2files`: resolved from the existing NCAA parameter library for nonstandard residues involved in the metal model.

Workflow-policy variables exposed by the parameterizer:

- `add_redcrd`
- `anglefc_avg`
- `bondfc_avg`
- `cut_off` through EnzyHTP `mcpb_cut_off`
- `ion_paraset`
- `large_opt`
- `scale_factor`
- `software_version`
- `sqm_opt`
- `xstru`

Settings derived from existing parameterizer attributes, not exposed as separate MCPB options:

- `force_field`, `gaff`, `water_model`: derived from `force_fields`.

MCPB.py steps:

1. `1`, `1a`, `1m`, `1n`: generate small, standard, and large model PDBs, fingerprint files, residue information, and QM input files.
2. `2`, `2s`, `2e`, `2z`, `2b`: generate pre/final frcmod files. The default `2`/`2s` path uses the Seminario method and needs QM log/fchk output. `2b` is useful for cheap smoke tests only.
3. `3`, `3a`, `3b`, `3c`, `3d`: fit RESP charges and generate mol2 files for renamed metal-center residues.
4. `4`, `4b`: generate bonded-model `*_mcpbpy.pdb`, `*_tleap.in`, and Amber outputs.

Primary target: bonded model `4`/`4b`.

## Development Tasks

### 1. Add Structure-Independent MCPB Options To AmberParameterizer

Add constructor/build arguments for MCPB policy without accepting structure-bound references.

Expected options include method enablement, MCPB process controls, and step choices. Do not add separate MCPB force-field, water-model, GAFF, ion-mol2-dir, QM-result-dir, or reuse/cache-policy options for this milestone. MCPB must derive force-field, water-model, and GAFF settings from `force_fields`.

The process-control options correspond to MCPB.py optional variables that change its internal workflow rather than describe a particular structure: `add_redcrd`, `anglefc_avg`, `bondfc_avg`, `cut_off`, `ion_paraset`, `large_opt`, `scale_factor`, `software_version`, `sqm_opt`, and `xstru`.

Done when:

- `build_md_parameterizer(..., metal_center_method="mcpb", charge_method="RESP", ...)` constructs an `AmberParameterizer` without needing a `Structure`.
- The object stores only MCPB policy/options, not metal-center objects or atom keys.
- MCPB rejects unsupported charge methods with a clear error before tleap; full RESP behavior is covered by `003-resp-charge-method.md`.

### 2. Resolve Metal Center Inputs Inside `run(stru)`

When `AmberParameterizer.run(stru)` sees MCPB enabled, it must inspect the supplied `Structure` and produce all MCPB structure-specific inputs there.

Responsibilities:

- Write a stable MCPB input PDB for the current `Structure`.
- Resolve metal centers and saved-PDB atom IDs.
- Resolve metal ion mol2 files from existing NCAA/parameter-library conventions.
- Detect donor atoms and metal-donor pairs from the current structure.
- Decide additional residues for the MCPB model from local geometry/policy.
- Resolve NCAA mol2/frcmod files for involved modified residues/ligands.
- Generate deterministic group names per metal center.

Done when:

- No constructor-time MCPB option contains `Atom`, `Residue`, `MetalUnit`, or `(chain, residue, atom)` keys.
- The MCPB input file generated during `run(stru)` contains the correct `ion_ids`, `original_pdb`, `ion_mol2files`, and any required model controls.

### 3. Drive MCPB.py And Collect Outputs

Implement the MCPB.py wrapper used by `AmberParameterizer.run(stru)`.

Responsibilities:

- Run steps `1`, `2`, `3`, and `4` using the configured step methods.
- Pass QM log/fchk files to step 2 when using `2s`.
- Validate generated `*_mcpbpy.pdb`, `*_mcpbpy.frcmod`, `*.mol2`, and `*_tleap.in`.
- Produce clear errors when required QM or ion mol2 inputs are missing.

Done when:

- MCPB.py failures are reported as actionable EnzyHTP errors.
- Required MCPB artifacts are generated and validated in the parameterizer work directory.

### 4. Integrate MCPB Outputs Into Final tleap

Use MCPB.py products inside EnzyHTP's normal Amber parameterization flow.

The first implementation should parse MCPB's generated `*_tleap.in` and reuse chemically relevant lines rather than reimplementing MCPB naming logic:

- `addAtomTypes` blocks.
- `loadmol2` lines for renamed residues.
- `loadamberparams *_mcpbpy.frcmod` and extra frcmods.
- `bond` commands for metal-donor and peptide reconnection bonds.

The implementation must account for MCPB.py's tleap unit name (`mol`) versus EnzyHTP's unit name (`a`).

Done when:

- EnzyHTP's generated final tleap input has the same chemically relevant MCPB lines as the manual MCPB/tleap workflow.
- Users no longer need to manually paste MCPB-generated `bond` commands into `additional_tleap_lines`.

## Completion Criteria

This task is complete when all of the following are true.

1. `AmberParameterizer` supports an MCPB bonded-model path enabled by structure-independent options.
2. All structure-specific MCPB facts are resolved inside `run(stru)`.
3. The 3PZW MCPB completion test runs and compares generated topology to `test/_interface/data/mcpb_answer/amber_parm.prmtop`.

6. Existing non-metal Amber parameterization behavior is unchanged.

## Explicit Non-Goals For This Milestone

- Reworking PDB chain-splitting or residue categorization.
- Passing structure-bound atom/residue keys into the parameterizer constructor.
- Automatically running Gaussian/GAMESS jobs on HPC. The implementation may require precomputed QM outputs for the first full test.
- Designing a persistent MCPB cache/reuse mechanism. That can be added later only with explicit fingerprint validation.
- Supporting every MCPB.py mode. Bonded model `4`/`4b` is the target.
